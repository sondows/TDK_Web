# ADM 권한 체계 전환 메모

현재 애플리케이션 권한은 다음 기준을 사용합니다.

- 활성 직원의 `admin_enabled = 1`: 일반 관리센터 로그인 및 조회·등록·수정
- `admin_enabled = 0`: 관리센터 로그인 차단
- `admin_security_owners` 구성원이며 개인 보안 비밀번호 인증이 유효함: 보안 메뉴 및 최고관리자 API
- POS/KDS/HOS 프로그램 권한은 각각 기존 직원별 권한 필드로 별도 확인

`staff.admin_permission`은 애플리케이션 ORM과 런타임 권한 판단에서 제거했습니다. 기존 DB 컬럼과 값은 이번 변경에서 보존되며, 쓰거나 읽지 않습니다. 이 컬럼의 물리적 삭제는 애플리케이션 배포와 데이터베이스 참조 확인 후 별도의 백업·복구 계획 및 승인으로 진행해야 합니다. 이 작업에는 DB 마이그레이션이 없습니다.

`20261018_admin_permission.sql`은 과거 권한 컬럼을 추가했던 이력 마이그레이션이며 새 환경에 과거 절차를 재현할 때만 참고합니다. `20261030_admin_owner_security.sql`의 초기 백필은 이전 ADM 허용 상태를 `admin_enabled`로 보존하기 위해 구 컬럼을 한 번 읽습니다. 이미 `admin_enabled` 값이 설정된 데이터에는 다시 적용되지 않습니다. 최고관리자 선택 조건은 `admin_enabled = 1`을 사용합니다.

기존 `role` 값은 POS 업무 권한 정책에 계속 사용됩니다. 이것은 ADM의 읽기·쓰기 등급이나 최고관리자 멤버십을 뜻하지 않습니다. 최고관리자 여부는 `admin_security_owners`의 직원 고유 ID로 판별합니다.

운영 반영 전에는 현재 애플리케이션이 요구하는 직원 PIN 및 최고관리자 스키마가 운영 DB에 준비되어 있는지 별도로 확인해야 합니다. 운영 DB 변경이나 NAS 배포는 이 변경에 포함되지 않습니다.
