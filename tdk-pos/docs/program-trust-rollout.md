# TDKON 프로그램 보안토큰 전환

## 인증 흐름

1. 처음 접속하면 ID와 마스터 비밀번호를 확인한다. 성공 시 해당 프로그램의 신뢰 토큰을 발급한다.
2. 직원에게 개인 PIN이 없으면 본인이 6자리 PIN을 등록한다. 있으면 기존 PIN을 입력한다. PIN 성공 후에만 업무 화면에 진입한다.
3. 이후에는 프로그램별 토큰을 서버에서 검증하고 직원 ID와 개인 PIN으로 로그인한다.
4. 토큰 폐기, 퇴사, 비활성화, 권한 해제는 기존 토큰과 직원 세션을 무효화한다.
5. 새 직원의 임시 비밀번호는 최초 인증 시 교체해야 한다. 임시 비밀번호만으로 장기 토큰을 발급하지 않는다.

과거 기기등록·승인 테이블과 초대 코드 테이블은 데이터 보존을 위해 남겨두지만, 인증 API는 더 이상 사용하지 않는다.

## 최고관리자 최초 등록과 기존 계정 마이그레이션 (2026-10-31)

최초 설정은 NAS 관리자가 서버를 `TDK_NAS_OWNER_SETUP=1` 모드로 실행한 동안, NAS 본체의 로컬 소켓에서만 사용할 수 있다. 요청 헤더의 권한 표시는 `server.cjs`가 실제 접속 소켓을 확인해 설정하며 클라이언트가 보낸 같은 이름의 헤더는 제거한다. 일반 LAN·외부 인터넷 접속은 등록 API를 사용할 수 없다. 작업 후 초기 설정 모드를 끄고 서버를 다시 시작한다.

개발 PC에서 `TDK_POS_TEST`를 사용할 때:

```powershell
$env:TDK_NAS_OWNER_SETUP = '1'
npm.cmd run dev
# 등록 작업 종료 후 서버를 중지하고, 다음 실행에서는 이 환경변수를 제거한다.
Remove-Item Env:TDK_NAS_OWNER_SETUP
```

새 설치에서 `security_bootstrap_state`의 완료 시각이 비어 있고 직원·최고관리자가 없으면 ADM 화면에 `최고관리자 최초 등록`을 표시한다. ID·마스터 비밀번호·확인값을 입력하면 OWNER 권한과 비밀번호 해시를 저장하고 완료 시각을 기록한다. 이미 완료한 설치에서는 다시 등록할 수 없다. 브라우저에 설치 코드나 복구 링크를 입력하지 않는다.

기존 최고관리자 `sondows`처럼 `staff.security_password_hash`가 NULL이면, 같은 NAS 로컬 초기 설정 모드에서 `/tdkadm/login`의 ID를 입력하고 포커스를 이동하거나 Enter를 누른다. 등록 가능한 활성 최고관리자이면 `마스터 비밀번호 등록` 창이 열린다. 등록 후 ID와 기존 PIN·권한·2차 인증 상태를 유지하고 비밀번호 입력란을 비운 `인증` 화면으로 돌아온다. 일반 접속에서 ID만 입력한 경우에는 상태 조회와 등록이 모두 거부된다. 실제 `sondows` 비밀번호는 본인이 직접 입력해야 하며 테스트에서 임의로 설정하지 않는다.

기존 `recover-owner-program-password.cjs`와 15분 일회용 복구 링크는 별도의 비밀번호 재설정 절차로 유지한다. 최초 등록에는 링크·`recovery=1`·PIN·초대 코드·기기 승인이 필요하지 않다. 비밀번호를 이미 등록한 계정은 최초 등록 API로 다시 변경할 수 없으며 별도 복구 절차를 사용한다.
## 테스트 및 운영 전환

1. 백업을 확인한 뒤 `20261030_temporary_program_password_test.sql`을 `TDK_POS_TEST`에 적용한다. 기존 직원 해시와 권한은 유지된다.
2. 테스트 DB에서 신규 직원 등록, 임시 비밀번호 교체, 기존 직원의 첫 인증, PIN 등록, 재접속, 퇴사 차단을 확인한다. 기존 최고관리자 계정은 수정하지 않고 임시 테스트 최고관리자로 NAS 복구 명령을 검증한다.
3. 운영 승인 후 백업과 필요한 운영 DB 마이그레이션을 별도로 확인한다. 새 이미지를 배포한 뒤 기존 최고관리자에게 마스터 비밀번호가 없으면 NAS 로컬 초기 설정 모드에서 본인이 등록한다. 이미 등록된 비밀번호를 잊었을 때만 별도 복구 링크를 사용한다.
4. 최고관리자의 ADM 최초 인증, PIN 로그인, 2차 보안 인증을 확인한 후 직원에게 임시 비밀번호를 발급한다.

기존 직원 코드, 개인 PIN 해시, 주문·매출 데이터, 관리자 2차 비밀번호는 변경하지 않는다. 운영 NAS 배포와 운영 DB 마이그레이션은 사용자 승인 후 진행한다.
